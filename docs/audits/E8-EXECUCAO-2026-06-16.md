**"Paridade verde" enganosa:** validadores só contam `.md` (existsSync + countMarkdownFiles), nunca abrem/executam. Verde = arquivo presente ≠ funciona. É o Risk 3 (False Parity) que o próprio plano jurava evitar.

## Mecanismo do Codex (defense-in-depth, 4 camadas)

Codex não tem hooks de tool-call → **sem paridade 1:1 de enforcement por design**. Estratégia em camadas:

1. **Git hook compartilhado** (`core.hooksPath`→`.sinapse-ai/git-hooks/`) — a única trava REAL e IDE-agnóstica; pega Claude E Codex no commit/push. **Prioridade #1.**
2. **AGENTS.md instrução forte** — enforcement soft (modelo lê por padrão); cobre o que não vira git hook (DDL destrutivo, `npm view` antes de install, não editar core/**).
3. **config.toml** (sandbox/approval) — alcance limitado; barra `--dangerously-bypass`.
4. **CI/publish** — smoke test server-side + branch protection (única garantia real de push-authority).

**Princípio honesto:** medir paridade por RESULTADO (smoke tests), não por existência de arquivo. O enforcement em tempo-real do save/exec do Claude é insubstituível no Codex hoje — assumido explicitamente.
