# Story 10.38 — Install: merge-only, no overwrite option

## Story

**As a** SINAPSE user installing or re-installing on a project that already has a `CLAUDE.md` (or `.env`),
**I want** the installer to ALWAYS merge existing config with SINAPSE templates — never offer the choice to overwrite,
**so that** my custom rules, agents config and env values can never be accidentally destroyed by running `npx sinapse-ai install`.

## Context

A real user incident (2026-04-13) revealed the installer UX allows users to destroy their own config. Investigation showed:

1. **`packages/installer/src/wizard/ide-config-generator.js:83-128`** (`promptFileExists`) — shows an interactive prompt with options `merge | overwrite | backup | skip`. Default is `backup` for greenfield. One wrong click and the user loses their CLAUDE.md custom rules.
2. **`packages/installer/src/config/configure-environment.js:78-108`** — same pattern for `.env`: shows `merge | backup | overwrite | skip` prompt.
3. **`bin/sinapse.js:788-789`** — exposes `--merge` / `--no-merge` flags. `--no-merge` explicitly asks for "legacy overwrite behavior" which is destructive.
4. **`bin/sinapse-init.js:568`** (LEGACY fallback installer) — uses plain `fse.copy(sourceRules, targetRules)` for `.claude/CLAUDE.md`, no merge at all — unconditionally overwrites.

`MarkdownMerger.migrateLegacy()` and `MarkdownMerger.merge()` already exist and are correct. The code just doesn't use them consistently.

Caio's directive: **"sempre será merge. Nunca dê opção de escolher."** Merge is the only safe behavior for distributors who are not developers (User Profile Safety Net, `~/.claude/CLAUDE.md`).

## Acceptance Criteria

**AC 1 — `promptFileExists` never prompts when merge is possible**
- Given an existing file that has a merge strategy (`hasMergeStrategy(filePath) === true`),
- When `promptFileExists()` is called,
- Then it returns `'merge'` directly without showing any inquirer prompt.
- And `forceMerge` / `noMerge` options are ignored (merge is the only behavior).

**AC 2 — `configureEnvironment` never prompts for existing `.env`**
- Given an existing `.env` with a merge strategy,
- When `configureEnvironment()` runs in interactive or quiet mode,
- Then it always executes the merge branch (`envAction === 'merge'`).
- Then no `select()` prompt is shown for `.env` handling.

**AC 3 — Files without merge strategy fall back to safe backup+write**
- Given an existing file whose extension has no registered merge strategy,
- When the installer needs to write the template,
- Then the installer creates a timestamped backup (`<file>.backup.<timestamp>`) and writes the new content.
- Then a message is shown: `"Backup criado em <path> antes de substituir"`.

**AC 4 — Legacy installer also merges CLAUDE.md**
- Given `bin/sinapse-init.js` is used as fallback installer,
- When copying `claude-rules.md` to `.claude/CLAUDE.md`,
- And the target file already exists,
- Then it runs `MarkdownMerger.merge()` instead of `fse.copy()`.
- And preserves 100% of user content.

**AC 5 — CLI flags deprecated gracefully**
- Given `npx sinapse-ai install --merge` or `npx sinapse-ai install --no-merge`,
- When the installer parses args,
- Then both flags are accepted as no-ops (for backward compatibility).
- Then help text (`--help`) no longer advertises `--no-merge`.
- Then help text states: "Merge is always enabled. Your existing config files are never overwritten."

**AC 6 — Tests cover all paths**
- Given a test suite run (`npm test`),
- Then existing CLAUDE.md (with and without SINAPSE markers) is preserved after install.
- Then existing `.env` values are preserved after install.
- Then no regression in non-TTY install path (Story 10.33).

## Scope

**IN:**
- `packages/installer/src/wizard/ide-config-generator.js` — rewrite `promptFileExists` to always return `'merge'` when possible
- `packages/installer/src/config/configure-environment.js` — remove `.env` prompt, always merge when possible
- `bin/sinapse.js` — update help text, keep flags as no-ops
- `bin/sinapse-init.js` — use `MarkdownMerger` for existing CLAUDE.md in legacy path
- `tests/installer/` — add regression test asserting CLAUDE.md preservation

**OUT:**
- Changing `MarkdownMerger` logic itself (already correct)
- Supabase/database config files (not touched by installer)
- Force reinstall (`--force`) — remains destructive by design, user opts in explicitly

## Dependencies

- Story 10.33 (non-TTY install) — must still pass
- Story 10.35 (--reconfigure) — unaffected

## Risks

- **Low:** Users who WANTED to overwrite lose that option. Mitigation: `--force` flag already exists for this, documented in help text.
- **Low:** Tests that asserted on prompt behavior might break. Mitigation: update test fixtures.
