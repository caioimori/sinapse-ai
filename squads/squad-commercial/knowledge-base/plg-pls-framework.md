# PLG & PLS — Product-Led Growth and Product-Led Sales

## Product-Led Growth (PLG)

### O que é PLG
PLG é o modelo onde o PRODUTO é o principal veículo de aquisição, conversão e expansão — não o time de vendas ou marketing. O produto "vende a si mesmo" através de valor imediato e viralidade.

**Empresas que definiram o modelo:**
- **Slack** — freemium → adoção em equipe → deal enterprise (via "Slack-ifcation" da empresa)
- **Dropbox** — free 2GB → viral sharing → Business plan
- **Zoom** — free meetings → departamento → company-wide
- **Notion** — free personal → team → enterprise
- **Figma** — free → team → enterprise (vendido por USD 20bi para Adobe)
- **Miro, Loom, Linear** — todos seguem padrão similar

### O Funil PLG
```
Free Signup → Activation → Engagement → Conversion → Expansion

Cada etapa tem uma ação crítica ("aha moment"):
  Slack: Primeira mensagem enviada em equipe
  Dropbox: Primeiro arquivo compartilhado
  Zoom: Primeira meeting com múltiplos participantes
  Notion: Primeira página criada e compartilhada
```

### Métricas PLG

| Métrica | Fórmula | Benchmark | O que Revela |
|---------|---------|-----------|-------------|
| **Time-to-Value (TTV)** | Dias até o usuário atingir "aha moment" | <7 dias (ideal <3) | Fricção na ativação |
| **Activation Rate** | % signups que completam ações-chave | 20-40% (varia por produto) | Qualidade do onboarding |
| **PQL (Product-Qualified Lead)** | Usuário que atingiu threshold de uso | Definido por produto | Sinal de compra real |
| **Free-to-Paid Conversion** | % free users que viram pagantes | 2-5% (freemium) / 15-25% (trial) | Monetização |
| **Viral Coefficient (K)** | Cada usuário traz quantos novos | >1 = crescimento orgânico | Produto se auto-distribui |
| **Expansion Revenue** | Receita de upgrades/expansão | >30% do total | Motor de crescimento |
| **DAU/MAU Ratio** | Usuários diários / mensais | >25% = alta engagement | Stickiness do produto |

### Freemium vs. Free Trial
| Modelo | Freemium | Free Trial |
|--------|---------|-----------|
| Acesso | Ilimitado (features reduzidas) | Completo por período limitado |
| Conversão | 2-5% | 15-25% |
| Awareness | Alta (mais usuários) | Menor |
| Melhor para | Produtos sociais/colaborativos (Slack, Figma) | Produtos de produtividade (HubSpot, Salesforce) |

## Product-Led Sales (PLS)

### O que é PLS
PLS combina PLG com sales-assist — o produto gera leads qualificados pelo uso, e vendedores entram estrategicamente para converter e expandir. Não é escolher entre PLG OU Vendas — é combinar os dois para maximizar.

**Diferença PLG vs. PLS:**
```
PLG puro: Produto → usuário → conversão automática → expansão automática
PLS: Produto → usuário ativo → sinal de PQL → vendedor entra → expansão dirigida
```

### Quando PLG precisa de Sales (triggers para PLS)
- Free tier atinge limite de uso → Sales ajuda no upgrade
- Single user → Sales identifica oportunidade de expandir para team/company
- **PQL score alto** → Sales faz outreach proativo no momento certo
- Enterprise features necessárias (SSO, admin controls, compliance, SLAs) → Sales obrigatório
- Deal > $XX K → ROI de um AE se justifica

### PQL (Product-Qualified Lead)
O PQL substitui o MQL em modelos PLG. É um sinal de comportamento no produto que indica prontidão para conversão.

**Framework para definir PQLs:**
```
PQL Threshold = Combinação de:
  1. Profundidade de uso (features críticas ativadas)
  2. Frequência (DAU/WAU nas últimas 2 semanas)
  3. Breadth (número de usuários na mesma conta)
  4. Recency (atividade nos últimos X dias)
  5. Intent signals (visitou página de pricing, convidou usuários, criou workspace)

Exemplo Figma:
  PQL = (Criou 5+ arquivos) AND (Compartilhou com 3+ pessoas) AND (Sessão >3 dias/semana)
  → Sinal de que o produto virou ferramenta de trabalho real
```

**PQL scoring típico:**
| Sinal | Peso |
|-------|------|
| Atingiu 80% do limite free | Alto (+5) |
| Convidou usuários externos | Alto (+4) |
| Usou features premium (trial) | Alto (+4) |
| Visitou página de preços | Alto (+5) |
| Utilizou produto >5 dias nos últimos 7 | Médio (+3) |
| Mais de 3 usuários na mesma conta | Médio (+3) |
| Inativo por 7+ dias | Negativo (-3) |

### PLS Motion — Como Funciona
```
1. Produto captura sinal de PQL
2. Sistema notifica Sales (CRM, Slack, email)
3. AE pesquisa conta (quem são? tamanho? fit?)
4. Outreach personalizado ("Vi que X usuários do seu time estão usando...")
5. Sales conversa de upgrade/expansion (não cold call — warm call)
6. AE fecha upgrade ou expande para enterprise
```

**Taxa de conversão PLS vs. Cold Outbound:**
- PQL → Customer: 20-35% (produto já prova valor)
- Cold outbound → Customer: 5-15%
- PLG + PLS: ~3x mais eficiente por deal do que sales-only

## PLG Maturity Model

| Nível | Descrição | Características |
|-------|-----------|----------------|
| **L1 — Trial** | Free trial básico, conversão manual | CTAs no produto, vendas reagem |
| **L2 — Freemium** | Tier free real com value contínuo | Viral loop, growth via produto |
| **L3 — PLG** | Produto como canal principal | PQL definidos, analytics de produto, automação |
| **L4 — PLS** | Produto + Sales coordenados | PQL → AE automático, expansion playbooks |
| **L5 — Growth OS** | Produto + Sales + CS integrados | Predictive expansion, community, ecosystem |

## PLG para Agências e Serviços

Agências e empresas de serviços podem aplicar princípios PLG:

**Equivalentes de PLG em serviços:**
- **Free audit / diagnóstico** = freemium (entrega valor antes de cobrar)
- **Template/ferramenta gratuita** = produto gratuito que gera leads
- **Relatório automatizado** = produto que escala sem headcount
- **Portal do cliente** = produto que aumenta stickiness e reduz churn

**Métricas adaptadas:**
- TTV → Tempo até o cliente ver primeiro resultado mensurável
- Activation → % de clientes que concluem onboarding e usam o serviço ativamente
- PQL → Cliente que usou X relatórios, participou de Y sessões, atingiu Z resultado
